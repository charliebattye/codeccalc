Notes on the numbers. ProRes and DNxHR figures use Apple's and Avid's published target data rates (constant, resolution/fps-scaled). XAVC-Intra Class 100/300/480 figures are derived from Sony's official XAVC operating-point tables (Class defines a coded-frame-size budget, not a literal resolution, so the same class is reused across HD/2K or 4K/QFHD/DCI4K variants). XAVC-L is rated by class rather than by frame rate — the class name is the bit rate — so those rows read from a per-mode table of Sony's class figures: 50 Mb/s for XAVC-L HD 50, 35 for HD 35, and 100 Mb/s at 24–30p stepping to 150 at 50–60p for XAVC-L 4K. Published card recording times for the FX6 and FX9 confirm the shape: one recording time is quoted across 24, 25 and 30p and another across 50 and 60p, where a frame-rate-proportional codec would differ at each. Modelling these as bits per pixel, as this tool previously did, read double the real figure at 60p. Sony X-OCN (LT/ST/XT) figures were originally estimated from Sony's published size relationships between the three flavors and ProRes 4444. They have since been checked against Sony's own VENICE and VENICE 2 file size calculator across the 8.6K 3:2, 8.2K 17:9 and 6K 3:2 sensor modes, and agree to within 0.5–2.6% — the residual being container overhead that Sony's total-data-rate figures include and these video-only figures don't. Sony set the X-OCN rate by sensor mode rather than output raster, so 3840×2160 and 4096×2160 record at the same rate while this tool scales by pixel count; the wider raster reads about 7% high. Canon Cinema RAW Light uses a compression ratio derived from a single official Canon data point (1 Gbps at 4096×2160, 25p, 12-bit). XF-AVC Intra is derived from Canon's published bitrate table. XF-AVC Long GOP has been withdrawn: it was averaged from two Canon data points that disagreed by over 30% (35 Mb/s at 50p against 24 Mb/s at 25p, same resolution), and since a Long-GOP bit rate does not scale with frame rate, one averaged figure could not have been right at more than a single operating point. It will return if Canon publish enough points to build a table. ProRes RAW and ProRes RAW HQ use estimated compression ratios (Apple doesn't publish these directly) — adjust the ratio slider if you have camera-specific figures. GoPro HERO13 Black figures are read from GoPro's own published SD card capacity table, converting each recording time on a 128 GB card into a bit rate, for both the Standard and High settings. They are per-mode figures rather than one bits-per-pixel value, because the camera's implied bits per pixel varies more than fivefold across its own modes: the encoder pins to a ceiling near 140 Mb/s at 5.3K60 and 4K120, and falls to about a third of that at 1080p30. Frame rates GoPro don't publish are interpolated between neighbouring published ones; anything outside that range reads as a dash rather than a scaled guess. GoPro state the HERO13's bit rate is highly variable with scene complexity, so treat these as static-scene estimates. DJI's Osmo Pocket 3 H.265 figure is still a single bits-per-pixel value scaled from DJI's own 130 Mb/s spec at 4K, because DJI publish no equivalent capacity table. It will read low at smaller rasters and lower frame rates for the same reason the GoPro entries once did — treat it as a rough estimate rather than a per-mode figure. Panasonic's AVC-Intra 4K-422 / All-I 400 figure is based on a Panasonic technical comparison stating both run "about 400 Mb/s" at 4K 30p (an earlier figure in the same document cites 320 Mb/s, so treat this as an approximate midpoint rather than an exact spec). Panasonic's LongGOP 150 has been withdrawn for the same reason as Canon's Long GOP entry: a single 150 Mb/s cap spread across every raster and frame rate as a per-pixel figure reads correctly at one operating point and wrongly at all the others. Sony's XAVC H-Intra HQ/SQ figures for the BURANO's 8K modes are derived from Sony's published 1200/800 Mb/s figures at 8K 30p. GoPro MISSION 1 Pro figures come from GoPro's published 256 GB card capacity table, split into the camera's three settings. Max is GoPro's stated constant 240 Mb/s rather than a figure derived from that table: the table rounds every Max entry to “2Hrs”, which would imply 284 Mb/s, so the stated spec is the better source. High and Standard are converted from the published times, with 8K High held to GoPro's stated 160 Mb/s ceiling. Those times are quoted only to the nearest half hour, so the shortest durations carry roughly ±13% uncertainty; the derived High ceiling of 162.5 Mb/s agreeing with GoPro's stated 160 to within 1.6% is the main check that the conversion is sound. Modes GoPro mark N/A, such as Max below 480 fps at 1080p, read as a dash rather than a substituted figure. GoPro Labs firmware can exceed these caps, which isn't modelled here. Uncompressed and RAW figures (ARRIRAW, REDCODE, Blackmagic RAW, CinemaDNG) are computed from sensor bit depth × pixel count × frame rate ÷ compression ratio — real-world RAW rates vary with image content, so treat these as planning estimates, not guarantees. H.264/H.265 rows are rough high-bitrate references for on-set proxy recording only, not camera-specific specs. In DIT / Data Wrangle mode, each camera's codec and resolution lists are a curated set of its main shooting modes, not the full permutation table a manufacturer publishes — high-frame-rate crop modes and windowed resolutions aren't included. Frame rates are scoped only for codecs with a published per-mode table, where the list narrows to the modes the manufacturer actually quotes; for bits-per-pixel and RAW codecs every frame rate is offered whether or not that camera reaches it, so check the camera's own specification before pricing an unusual one. Audio assumes uncompressed linear PCM per stream. Storage figures use decimal GB/TB (1 GB = 1000 MB), matching card and drive marketing capacities.
