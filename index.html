Notes on the numbers. ProRes and DNxHR figures use Apple's and Avid's published target data rates (constant, resolution/fps-scaled). XAVC-Intra Class 100/300/480 figures are derived from Sony's official XAVC operating-point tables (Class defines a coded-frame-size budget, not a literal resolution, so the same class is reused across HD/2K or 4K/QFHD/DCI4K variants). XAVC-L figures come from Sony's Long GOP VBR ceilings, which don't scale as cleanly with resolution/fps as intra codecs do, so treat the XAVC-L rows as rough guides rather than exact per-frame-rate targets. Sony X-OCN (LT/ST/XT) figures are estimated from Sony's published size relationships between the three flavors and ProRes 4444, not from a direct per-resolution spec table — treat as approximate. Canon Cinema RAW Light uses a compression ratio derived from a single official Canon data point (1 Gbps at 4096×2160, 25p, 12-bit). XF-AVC Intra is derived from Canon's published bitrate table; XF-AVC Long GOP is averaged from two Canon data points that disagreed with each other by over 30% (35 Mb/s at 50p vs. 24 Mb/s at 25p, same resolution) — like XAVC-L, it's a Long-GOP codec whose real bitrate doesn't scale linearly with frame rate, so treat this one as the roughest estimate in the RAW/Long-GOP set. ProRes RAW and ProRes RAW HQ use estimated compression ratios (Apple doesn't publish these directly) — adjust the ratio slider if you have camera-specific figures. GoPro's H.265 figure is based on its official 120 Mb/s standard-bitrate spec at 5.3K60, which GoPro states as a flat cap across its frame-rate range rather than one that scales per fps, so treat it as approximate at other resolutions/frame rates. DJI's Osmo H.265 figure works the same way, based on DJI's own 130 Mb/s spec at 4K. Panasonic's AVC-Intra 4K-422 / All-I 400 figure is based on a Panasonic technical comparison stating both run "about 400 Mb/s" at 4K 30p (an earlier figure in the same document cites 320 Mb/s, so treat this as an approximate midpoint rather than an exact spec); LongGOP 150 uses Panasonic's own published 150 Mb/s cap — like XAVC-L, this is a Long-GOP codec, so its real-world bitrate doesn't scale as linearly with frame rate as the intra codecs above; the 150 Mb/s figure is most accurate near the frame rate Panasonic quotes it at rather than across the full range. Sony's XAVC H-Intra HQ/SQ figures for the BURANO's 8K modes are derived from Sony's published 1200/800 Mb/s figures at 8K 30p. The GoPro Mission's H.265 figure is based on GoPro's official 240 Mb/s standard-bitrate spec at 8K60 (a cap GoPro states was set to meet Netflix's published capture-bitrate requirement) — GoPro Labs firmware can push this higher, which isn't modeled here. Uncompressed and RAW figures (ARRIRAW, REDCODE, Blackmagic RAW, CinemaDNG) are computed from sensor bit depth × pixel count × frame rate ÷ compression ratio — real-world RAW rates vary with image content, so treat these as planning estimates, not guarantees. H.264/H.265 rows are rough high-bitrate references for on-set proxy recording only, not camera-specific specs. In DIT / Data Wrangle mode, each camera's codec and resolution lists are a curated set of its main shooting modes, not the full permutation table a manufacturer publishes — high-frame-rate crop modes and windowed resolutions aren't included. Audio assumes uncompressed linear PCM per stream. Storage figures use decimal GB/TB (1 GB = 1000 MB), matching card and drive marketing capacities.
